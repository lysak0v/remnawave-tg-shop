## [3.5.3] — 2026-11-16

Миграций БД нет. Новая переменная `NALOGO_TIMEZONE` (по умолчанию `Europe/Moscow`).

### Fixed

- Чеки «Мой налог»: время операции передаётся в часовом поясе `NALOGO_TIMEZONE` со смещением
  (`2026-11-16T19:40:10+03:00`), а не в UTC — чек показывает московское время, и оплата сразу после
  полуночи по Москве датируется правильным днём и месяцем. Значение `UTC` возвращает прежнее поведение.

## [3.5.2] — 2026-11-16

Миграций БД нет, новых переменных нет.

### Changed

- «Мои устройства»: кнопки — призыв к действию со значком типа устройства («💻 Удалить №1»), по 2 в ряд;
  при нечётном количестве последняя — во всю ширину, «Назад» — отдельной строкой. Номер в списке — цифра-эмодзи
  (1️⃣ … 🔟, дальше «№11»). Формулировки «отключить» → «удалить» в подсказке, подтверждении и сообщениях.

## [3.5.1] — 2026-11-16

Миграций БД нет, новых переменных нет.

### Changed

- «Мои устройства»: «Последний запрос» — только давность без даты и времени («сегодня», «вчера», «2 дня назад»,
  «21 день назад», «40 дней назад»; русские формы склоняются). HWID в списке и в подтверждении сокращён до
  первых и последних 5 символов (`A05AF*****288B6`), чтобы строка помещалась на телефоне; окончание HWID в
  кнопках — тоже 5 символов, совпадает с концом строки HWID.

## [3.5.0] — 2026-11-16

Миграций БД нет, новых переменных нет.

### Added

- «Мои устройства»: дата и время последнего запроса подписки с устройства (`updatedAt` записи HWID — панель
  обновляет его при каждом запросе подписки) и давность («сегодня», «вчера», «N дн. назад»). Устройства без
  запросов дольше 30 дней отмечены 💤, под списком — пояснение. То же — на экране подтверждения отключения.

### Changed

- Даты в «Мои устройства» — в часовом поясе сервера (раньше дата подключения показывалась по UTC).

## [3.4.0] — 2026-11-16

Миграций БД нет, новых переменных нет. Если `START_COMMAND_DESCRIPTION` задан, он заменит «Меню / Menu» для
языка по умолчанию — уберите его, чтобы был двуязычный текст.

### Added

- «Мои устройства»: читаемый список — значок по типу устройства, название (модель или имя компьютера без
  архитектуры и повторов), ОС с версией и приложение с версией, дата подключения и HWID. Кнопки отключения —
  номер, название и окончание HWID (удлиняется, если у двух устройств совпадает), поэтому одинаковые устройства
  различимы. Перед отключением — подтверждение.
- Команда `/subscription` (в меню вместо `/connect`; `/connect` по-прежнему работает).

### Changed

- Меню команд — один короткий текст на двух языках: «Меню / Menu», «Подписка / Subscription», «Язык / Language».
- «Ссылка на конфигурацию» и «Ключ подключения» → «Ссылка на подписку» (en — «Subscription link»).
- Ключи локалей устройств получили новые плейсхолдеры (`{emoji}`, `{name}`, `{details}`, `{hwid_short}`,
  `{button_name}`); прежние (`{device_model}`, `{platform}`, `{os_version}`, `{user_agent}`) передаются тоже.

## [3.3.0] — 2026-11-16

Миграций БД нет, новых переменных нет.

### Added

- Меню команд Telegram: `/start`, `/connect` (моя подписка и подключение), `/language`. Описания — из локалей
  (`bot_command_start`, `bot_command_connect`, `bot_command_language`), отдельное меню для каждого языка плюс
  общее на `DEFAULT_LANGUAGE`.

### Changed

- `START_COMMAND_DESCRIPTION` больше не обязателен для меню и задаёт текст `/start` только для языка по умолчанию;
  для остальных языков — `bot_command_start` из локалей.

## [3.2.0] — 2026-11-16

Миграций БД нет. Если тексты бота правились в смонтированной `locales`, перед обновлением перенесите
изменённые ключи в `locale_overrides/<lang>.json` и смонтируйте эту папку (см. README, «Свои тексты бота»).

### Added

- Свои тексты поверх встроенных локалей: папка `LOCALE_OVERRIDES_PATH` (по умолчанию `locale_overrides`)
  с `ru.json` / `en.json`, где только изменённые ключи. Новые ключи при обновлениях приходят с образом.
- Тесты локалей в CI: одинаковый набор ключей в ru и en, наличие всех ключей, на которые код ссылается
  буквально, совпадение плейсхолдеров `{…}` между языками.

### Changed

- `docker-compose*.yml` монтируют `./locale_overrides`, а не всю папку `./locales`. **Если вы правили тексты в
  смонтированной `locales`**, перенесите только изменённые ключи в `locale_overrides/<lang>.json`.
- Кнопка языка: «🌐 Язык / Language» и «🌐 Language / Язык».

### Fixed

- Тексты ошибок активации триала (`trial_activation_failed*`, `user_not_found_for_trial`) отсутствовали в
  локалях — пользователь видел имя ключа.
- Удалён неиспользуемый ключ `admin_promo_invalid_discount_percentage` (был только в ru).

## [3.1.0] — 2026-11-16

Требования без изменений (Remnawave ≥ 3.0), миграций БД нет. Новые переменные — `TRIAL_USER_TAG`,
`PAID_USER_TAG`, `PROTECTED_USER_TAGS`, `PANEL_DESCRIPTION_TIMEZONE` (все необязательные). Если локали
смонтированы с хоста, обновите их: добавлены ключи `account_disabled_in_panel`, `admin_paid_while_disabled`.

### Added

- Теги пользователей в панели: при активации триала ставится `TRIAL_USER_TAG`, при оплате подписки или
  пакета трафика (все провайдеры, включая автопродление) — `PAID_USER_TAG`. Теги из `PROTECTED_USER_TAGS`
  (например, `FREE`, выставленный вручную) бот не перезаписывает. По умолчанию выключено.
- Оплата недоступна пользователю, отключённому в панели (`DISABLED`): бот отказывает при выборе тарифа.
  Если оплата всё же прошла (старая кнопка, отключили после выставления счёта), срок продлевается,
  статус остаётся `DISABLED`, админу приходит уведомление.

### Changed

Панель — источник правды: пользователей и подписки заводят не только через бот.

- Сквады пользователя **дополняются** `USER_SQUAD_UUIDS`, а не заменяются ими (триал, оплата, бонусные дни,
  реферальный бонус). Внешний сквад ставится, только если у пользователя его нет.
- Описание пользователя в панели **дополняется**: при смене профиля Telegram бот добавляет строку
  `[дата время пояс] username | Имя Фамилия` (пояс — `PANEL_DESCRIPTION_TIMEZONE`), текст админа сохраняется.
  Описания в прежнем формате (username, имя, фамилия построчно) не переписываются, пока профиль не изменился.
- Кнопка триала, отказ в триале и привязка к пригласившему учитывают панель: пользователь, который уже есть
  в панели, считается имевшим подписку, активный в панели — активным. Если панель недоступна, триал не
  предлагается.

### Fixed

- Триал больше не выдаётся пользователю, который уже есть в панели (заведён вручную или до последней
  синхронизации) или у которого защищённый тег: раньше триал перезаписывал ему срок, лимит трафика и сквады.
  После такого отказа кнопка триала в меню больше не показывается.
- Синхронизация при старте и смена профиля Telegram больше не стирают описание пользователя в панели.
- Реферальный бонус пригласившему на запасном пути считается от `expireAt` панели (раньше — от текущего
  момента, что могло сократить срок) и не включает пользователя, отключённого в панели.

## [3.0.0] — 2026-10-25

Первый релиз форка. База — [kavore/remnawave-tg-shop](https://github.com/kavore/remnawave-tg-shop) `9ef68bf`
(v2.7.0 + 7 коммитов, 2026-03-17). Проверено на Remnawave backend 3.4.7 / node 3.4.3.

### ⚠ BREAKING CHANGES

- **Требуется Remnawave ≥ 3.0.** Панель 3.x удалила `users.uuid`; пользователи адресуются числовым `id`.
  С панелью 2.x эта версия не работает.
- **Миграция БД `0004_panel_user_id`** (применяется автоматически при старте): добавляет `users.panel_user_id`
  (уникальный индекс) и `subscriptions.panel_user_id`, снимает `NOT NULL` с `subscriptions.panel_user_uuid`.
  Старые колонки `panel_user_uuid` сохраняются как legacy. Заполнение `panel_user_id` для существующих
  пользователей — автоматической синхронизацией при старте (по `telegramId`) или заранее, SQL по карте
  `uuid → id`, выгруженной из панели до обновления.
- **Уведомления об окончании подписки** приходят только по событию панели `user.expiration`
  (вместо удалённых `user.expires_in_*` / `user.expired_24_hours_ago`). В панели нужны
  `WEBHOOK_ENABLED=true`, `WEBHOOK_URL=https://<бот>/webhook/panel`, `WEBHOOK_SECRET_HEADER` = `PANEL_WEBHOOK_SECRET` бота
  (≥ 32 символов, только `[A-Za-z0-9]`), `EXPIRATION_NOTIFICATIONS_ENABLED=true`,
  `EXPIRATION_NOTIFICATIONS=[-72, -48, -24, 24]`.
- **Шифрование ссылок Happ (CRYPT4) недоступно:** эндпоинт `/system/tools/happ/encrypt` удалён в панели;
  используйте `CRYPT4_ENABLED=False`.

### Added

- Продление оплаченных периодов (все платёжные провайдеры) и бонусных дней (промокоды, рефералы, админ)
  считается **от срока в панели** (`expireAt`), а не от копии в БД бота; для только что созданного
  пользователя панели — от текущего момента (#1).
- Тесты (pytest): клиент API панели по контракту 3.4.x, вебхуки панели, расчёт базы продления.
- CI (GitHub Actions): pyflakes (неопределённые имена), pytest, alembic upgrade/downgrade/upgrade на PostgreSQL 17,
  сборка образа linux/amd64 и публикация в `ghcr.io/lysak0v/remnawave-tg-shop` (из `main` и тегов `v*`).

### Changed

- Поиск пользователя по Telegram ID — `GET /users/stream?telegramId=` (точное совпадение, пагинация курсором)
  вместо удалённого `/users/by-telegram-id`.
- `PATCH /users`, действия `enable/disable`, `DELETE`, устройства (`/hwid/devices/{userId}`,
  `POST /hwid/devices/delete {userId, hwid}`) — по числовому `id`.
- Синхронизация с панелью сопоставляет пользователей по `id`/`telegramId`.
- Карточка пользователя в админке показывает «ID в панели» (новый ключ локализации `admin_user_panel_id_label`).
- Образ в примерах `docker-compose*.yml` — `ghcr.io/lysak0v/remnawave-tg-shop`.
- Обработка вебхука `user.expiration` и переход на числовой id портированы из
  [gldkru/remnawave-tg-shop](https://github.com/gldkru/remnawave-tg-shop) (`1251bb7`, `639c72f`) с доработками.

### Fixed

- Ответ «не найден» распознаётся по коду из `details.errorCode` (`A025`/`A062`) или HTTP 404; раньше код
  читался с верхнего уровня ответа и проверка не срабатывала. `A040` больше не считается «пользователь удалён».
- `DELETE /users/{id}` с пустым ответом 2xx считается успешным.
- Исправления в портированном коде: падение карточки пользователя в админке (срез по числовому id),
  неопределённая переменная в синхронизации, утерянный параметр `traffic_limit_strategy` для ГБ-пакетов.

### Removed

- Workflow публикации образа в Docker Hub upstream-проекта.
